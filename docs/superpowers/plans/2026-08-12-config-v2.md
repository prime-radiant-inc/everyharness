**Goal:** Replace the accreted config shape with a coherent one — tagged bootstrap union, all per-harness intent under `harnesses.<name>`, `bump:` renamed to `release:` — as a clean break with NO backward compatibility (Jesse's explicit call: only his plugins use this). **Tech Stack:** TypeScript/vitest only. No container work (outputs don't change).

## The v2 schema (spec — binding)

```yaml
# identity — unchanged
name: superpowers
version: 6.2.0
description: ...
author: { name: ..., email: ... }
license: MIT
repository: https://github.com/obra/superpowers
homepage: ...
keywords: [a, b]

# components — unchanged
components: { skills: skills, commands: commands, agents: agents, hooks: hooks/hooks.json, mcp: .mcp.json }

# bootstrap — tagged union; invalid states unrepresentable
bootstrap: generate                 # string literal
# bootstrap: none                   # string literal (same as omitting the key)
# bootstrap: { skill: using-superpowers }   # object form only when a parameter is needed

# harnesses — ALL per-harness intent in one place
harnesses:
  exclude: [devin]                  # unchanged
  claude-code:                      # any adapter name; unknown names are ConfigErrors (typo-catching)
    hooks: own                      # 'generated' (default) | 'own' — replaces bootstrap.emitHooks;
                                    # 'own' = plugin ships hand-crafted hooks, everyharness emits no
                                    # hook files and forces no manifest hooks pointer for this harness.
                                    # Only valid on hook-emitting harnesses (claude-code, cursor) AND
                                    # only when bootstrap is skill/generate — else ConfigError.
    manifest:                       # replaces harnesses.overrides.<name>; null delete-sentinel unchanged
      repository: null

# marketplace — unchanged (cross-harness distribution artifact; stays top-level on principle)
marketplace: { name: ..., description: ..., source: repository, category: ..., tags: [...], strict: false }

# release — replaces bump: (same semantics, renamed to describe intent; CLI command stays `everyharness bump`)
release:
  files: [{ path: release.json, field: version }]
  audit: { exclude: [CHANGELOG.md] }
```

**Old-syntax hard errors (each names the replacement):**
- `bootstrap: { none: true }` / `{ generate: true }` → `bootstrap is now a tagged value: use "bootstrap: none", "bootstrap: generate", or "bootstrap: { skill: <name> }"`
- `bootstrap.emitHooks` (any form) → `bootstrap.emitHooks moved: set harnesses.<name>.hooks: own`
- `harnesses.overrides` → `harnesses.overrides moved: put manifest patches under harnesses.<name>.manifest`
- `bump:` → `bump: was renamed: use release: (same fields)`

**Resolved internal model (binding for all consumers):**
```ts
export type BootstrapMode = { kind: 'none' } | { kind: 'generate' } | { kind: 'skill'; skill: string }
export interface HarnessSettings { hooks: 'generated' | 'own'; manifest?: Record<string, unknown> }
// EveryharnessConfig changes:
//   bootstrap: BootstrapMode                          (no emitHooks member)
//   harnesses: { exclude: string[]; settings: Record<string, HarnessSettings> }
//   release?: { files?: {path,field}[]; audit?: { exclude?: string[] } }   (was bump)
// shared.ts: bootstrapEmitsHooks(config, harness) => bootstrap.kind !== 'none' && (settings[harness]?.hooks ?? 'generated') === 'generated'
```

**Validation rules:** harness keys under `harnesses:` other than `exclude` must be known adapter names (the registry in src/adapters/index.ts) — unknown → ConfigError naming the key and listing valid names; `hooks: own` on a non-hook-emitting harness (anything but claude-code/cursor) → ConfigError; `hooks: own` anywhere with `bootstrap: none`/absent → ConfigError (nothing to suppress); `manifest` value must be a plain object.
